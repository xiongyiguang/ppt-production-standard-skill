# 售前常用关系画法

用于内容关系已明确、需要构图指导的正文页。按当前页面选读，不要求整读或套用固定节点数；图中对象、关系与条件以项目材料为准。逐页记录、表格判据、重复结构和状态执行[内容设计](content-led-design.md)，原生对象、主题色、字号及连接器执行完整规范。下面是抽象结构，不是已通过PowerPoint视觉验收的样页。

## 1. 职责交接与协同

**输入与选型**：需要参与角色、共同业务对象、动作和交付／审批边界。读者核对谁负责哪些事项时可用职责矩阵；读者理解一件事怎样跨角色完成时，用角色分区和交接路径。

```text
业务角色A：发起事项 ──申请材料──→ 业务角色B：复核
                                     │通过／授权依据
                                     ↓
业务角色C：执行 ←──已确认任务────── 交付入口
```

按真实动作顺序对齐角色区，交接线上标传递对象或条件；仅角色交接重要时采用泳道。没有先后关系的协作采用围绕业务对象的协作地图，不硬串流程。异常补正只在材料有依据时加入。

**验收**：能看出谁向谁交付什么、边界在哪。未知批准权限标待确认，不能把协作画成汇报层级；若主要任务是交接，只有“角色＋职责描述”表不足以通过。

## 2. 需求到能力与证据映射

**输入与选型**：需要原始需求、已确认能力和对应依据；逐项响应或核对覆盖时，对照表可以成立。存在多个需求共享能力或跨能力依赖时，使用两侧映射或中间公共能力区域。

```text
需求A ─┐                 ┌─ 交付／证据A
       ├→ 共享能力 ───────┤
需求B ─┘                 └─ 交付／证据B
需求C ──→ 专项能力 ───────── 对应证据C
```

需求与能力分区，连接线表示覆盖而非实施顺序；共享能力只出现一次。映射多而交叉时按已确认主题拆页，保留总览和对应标识，详细核对放辅助表。不能为减少线条补造分类。

**验收**：需求覆盖、共享关系和证据出处可追溯；区分既有能力、拟建设内容与待确认项。“需求—响应”逐项表可保留，但不能隐藏关键依赖或把计划能力写成已验证事实。

## 3. 业务对象、状态与范围

**输入与选型**：需要核心对象、关联对象、归属／引用关系或状态变化依据。对象之间的关联用对象地图；一个对象怎样变化用状态路径；两类关系多时分为总览与展开，不在同一张图里混成无语义箭头。

```text
[客户／组织] ──归属或关联── [业务事项] ──引用── [相关资料]
                               │
                           [已确认状态路径]
```

核心对象占主要位置，内外部对象按真实范围分区，线旁写关系名称；数量关系只有来源明确时才写一对多等。状态路径标触发动作和已知条件，具体字段可放对象下方或辅助表。

**验收**：对象名称一致，归属、关联与状态迁移不混用。只有“模块名称＋功能描述”无法替代业务关系；无关联依据时保留对象分类清单并标缺口。

## 4. 架构调用、数据路径与横向治理

**输入与选型**：需要有依据的业务入口、组件、数据对象、调用或读写关系及接口边界。用分层区域表达位置，用带语义的连接器表达交换；治理范围确实跨层时采用侧栏或跨层区域。

```text
业务入口 ──请求──→ 应用组件
                       │调用／读写对象
                       ↓
                   公共能力 ──读写── 数据对象
外部系统 ──已知接口──→ 接入组件        │
                       [相关治理覆盖范围]
```

主路径先画清，再补相关支撑；治理与外部接口贴近其作用范围。连线密集时拆总体层级、专项数据路径或部署页，保持组件名称与跨页标识一致。不存在调用依据时标待确认，不用装饰箭头补图。

**验收**：读者能看出业务在哪实现、交换什么、数据在哪里、接口从哪里接入及治理覆盖哪些对象。分层矩形本身不构成问题；只有层名或仅在表格长句中描述调用而画面不可见时判待改。不能为丰富架构虚构技术栈、容量或承诺。

## 5. 界面截图与业务讲解

**输入与选型**：需要真实界面原图、演示任务、可见字段和说明依据。以能说明业务操作的截图区域为主视觉，少量标注连接到真实位置；讲解流程重要时用动作路径配截图，字段核对重要时可附对照表。

```text
[代表性真实界面／可读重点区域] ←── 标注A：可见操作及其作用
                            ←── 标注B：可见字段或结果
[必要上下文／流程衔接／已确认业务判断]
```

先保证截图内业务文字可读，再安排说明。整屏与局部放大并用时标明放大位置；截图之间的箭头只有真实操作关系成立时使用。图像保留原貌，截图线条执行现有统一母样，不能用AI重画字段或状态。

**验收**：标注与可见对象逐项吻合，截图足以支持说明；原型演示信息与已确认业务事实区分。不存在真实界面时用明确标注的示意结构，不冒充截图。图片页也必须说明其主体结构为何支持本页阅读任务。
