# 参考图、SVG 与图标重建工作流

仅在输入包含 PPT 截图、页面图片、PDF 渲染页、扁平化幻灯片，或用户明确要求重建/改善图标时读取本文件。imagegen生成参考图的构图借鉴按[版式研究与原生重构](imagegen-layout-reconstruction.md)执行；用户明确交付主体位图时按[主体图片替换](imagegen-content-replacement.md)执行。主技能、所选模板和《PPT 制作规范》的要求始终优先。

## 1. 先定义可编辑目标

默认交付“PowerPoint 原生对象可编辑”：

- 标题、正文、标签、卡片、表格、连接线、流程、图表和背景均为原生 PowerPoint 对象。
- 通用图标优先主题联动的原生或可编辑矢量对象；照片、复杂插画及保留的SVG/PNG为独立图片对象，可单独选择、移动、缩放、裁剪和替换。
- 图标内部是否为可编辑路径必须单独说明；普通 SVG/PNG 图片对象不等于 PowerPoint 原生路径。
- 整页 SVG 插入 PowerPoint 后通常仍是一个图形对象。除非已实际转换、检查并验证内部对象，否则不得把它描述为“文字和形状均可编辑”。

SVG 页面可作为可维护的源文件或中间稿，但不得替代原生 PPT 对象重建。若用户只要求像素级复刻且接受扁平结果，先明确该交付的编辑限制。

## 2. 建立页面清单

按页面顺序记录：

- 来源文件、页码、画面比例和清晰度。
- 可直接确认的文字、图表数据、对象层级和阅读顺序。
- 每个视觉素材的语义、位置、尺寸、背景、颜色、来源与目标编辑方式。
- 模糊、遮挡、无法辨认或需要推断的内容。

不得从低清画面猜造正文、数字、Logo、产品界面或品牌标识。无法确认时保留待确认项。

案例页必须先把“页面文字”和“视觉证据”拆开：标题、副标题、案例说明、建设内容、指标、口径、标签、结论和来源说明归入原生文字层；产品 UI、现场照片、原始图表和必要专业图示归入视觉证据层。旧页页眉、长段说明和指标区不得作为截图的一部分继续带入新页。

## 3. 视觉素材来源顺序

按以下顺序选择素材来源：

1. 项目目录中的原始照片、系统导出、设计源文件和客户提供原件。
2. 源 PPTX 中与目标页面关联的原始媒体、SVG/EMF、图表对象及裁剪参数；不要把整页截图当原图。
3. 源 PDF 中可提取的嵌入位图或矢量对象。
4. 所选模板、现有品牌资产或已获授权的项目素材。
5. 使用 PowerPoint 原生形状、主题联动 SVG 或可编辑矢量重新绘制通用图标和结构图。
6. 确实无法提取原对象时，使用源 PowerPoint/PDF 高分辨率渲染后精确裁切。PDF 默认从 300 DPI 起步；细小 UI 文字采用 450–600 DPI。
7. 仅在普通非事实型插图缺失、视觉风格确实复杂且生成式重建有价值时，使用 `imagegen`；既有低清截图只有在前述来源均不存在且用户接受局限时才可保留。

禁止使用图像生成重做 Logo、官方品牌标识、认证标志、产品 UI、数据图表和带有事实含义的截图。不得把通用图标库或生成式素材冒充原始素材。

不得用 AI 放大、锐化、涂抹或重绘来“修复”事实型 UI、指标或案例证据。应回到源文件提取原对象，或从源页高分辨率渲染后精确裁切。每张保留图片登记来源文件、页码/幻灯片、媒体部件或裁切框、原始像素、输出裁切像素、展示尺寸和可读性结论；照片/普通界面的源像素至少达到最终显示像素的 1.5 倍，包含细小文字的 UI 宜达到 2 倍。

从用户提供的来源中提取独立图片并非一律禁止，但必须满足授权、清晰度和用途要求；不要从整页截图裁下一块带背景、文字或相邻对象的区域充当“可编辑图标”。

## 4. 主题联动与颜色

- 通用图标优先用 PowerPoint 原生形状或真正引用所选主题槽位的矢量对象。
- 彩讯科技和中国移动素材分别服从各自模板，不沿用附件示例中的固定橙灰配色。
- 生成的 PNG、普通固定色 SVG、照片和截图不能随 PowerPoint 主题自动联动，应作为媒体例外记录。
- 如需主题联动，使用 `schemeClr` 或等效机制重建可见矢量对象；仅把 RGB 改成品牌色数值仍不合格。
- Logo、客户品牌、照片、产品截图和明确标准色保持原色，不把这些例外扩散为全页配色。

## 5. 使用图像生成重建图标

调用前先查看来源页面并写出语义清单。每张图标表控制在能清楚辨认的数量；图标密集时分批生成。

提示词至少应约束：

- 只生成清单中的独立图标，不生成标题、标签、中文、英文、数字、Logo、水印、卡片、页面背景或无关连线。
- 语义、构图、线条粗细、圆角、填充/描边方式和视觉重量与来源一致。
- 图标之间留足白边，边缘完整，不粘连、不裁切；需要深色背景版本时单独生成白线/白色版本。
- 配色服从当前所选模板；如果后续需要主题联动，优先生成单色或中性素材，再用原生矢量重建。

生成后逐个核对语义。出现伪文字、合并、缺失、重复、变形、阴影污染或页面碎片时重新生成，不用激进裁切掩盖问题。

可对干净的白底图标表运行：

```powershell
python scripts/extract_icon_components.py "icon-sheet.png" --out-dir "icons/page-01" --dilate 2 --padding 20
```

组件提取只是机械分割。必须把输出数量与语义清单逐项核对并人工建立映射；一个多部件图标被拆开或相邻图标被合并时，重新生成更疏的图标表或改用明确裁切框。

## 6. SVG 源文件

- 画布比例取自所选模板，16:9 时可使用 `viewBox="0 0 1920 1080"`；不要用固定画布覆盖模板真实比例。
- 文字使用 `<text>`/`<tspan>`，结构使用 `<rect>`、`<circle>`、`<path>`、`<line>`、`<polyline>` 等矢量元素。
- 每个图标使用独立 `<image data-icon-key="...">`，保持原始宽高比和足够分辨率。
- 不在最终 SVG 中放置整页来源截图，不把包含文字的大块页面区域烘焙成图片。
- 避免依赖导出器不稳定支持的 `foreignObject`、复杂 CSS、滤镜、遮罩和脚本。需要时转换为安全的基本形状。
- 自包含源文件可用 `scripts/embed_svg_icons.py` 嵌入映射素材，再运行验证：

```powershell
python scripts/embed_svg_icons.py "svg/page-01.svg" "svg/icon-map.json" --output "svg/page-01-embedded.svg"
python scripts/verify_svg.py "svg/page-01-embedded.svg" --require-embedded-images --forbid-full-page-raster --strict-export-safe
```

## 7. 构建 PPTX

1. 从权威模板的真实副本开始，普通内容页绑定其实测内容页版式。彩讯 2026 主模板为“2_内容1”，中国移动和旧彩讯 V2 为“内容页1”。
2. 先按来源画面重建信息层级，再依本规范校正字体、字号、主题色、形状层级、间距和可读性。
3. 使用 PowerPoint 原生对象重建文字、卡片、表格、连接线和图表；不要把整页 SVG 或截图铺成背景来伪装完成度。
4. 每个图标或插图独立插入。通用图标优先 SVG，复杂生成式插图可用透明 PNG；两者都需验证透明边缘、比例和单独选择能力。
5. 保留原始输入，输出新的版本文件。SVG、图标、映射和来源清单作为可选源包交付。
6. 案例页的标题、副标题、说明、指标、标签、结论和页码全部用原生 PowerPoint 对象重建；旧页截图仅裁出真实 UI、照片、图表和必要视觉证据。
7. 重复页眉骨架——左品牌图、标题占位符、右企业 Logo、页脚/结论区和页码——必须从权威模板测量并逐页核对，不从参考图近似描摹。

## 8. 验收

除主技能的模板审计外，至少完成：

1. 运行 `scripts/verify_pptx_text.py` 检查文本编码和占位残留。
2. 通过 Microsoft PowerPoint 导出全部重建页面；渲染目录应为新目录或空目录。
3. 逐页对照来源图，检查信息完整性、阅读顺序、层级、间距、裁切、透明边缘、颜色、图标语义和视觉重量。
4. 在 PowerPoint 中抽查文字、形状、连接线、表格/图表和每个媒体素材是否可按声明方式单独编辑。
5. 发现缺陷后修正并重新渲染受影响页；首稿已满足实际检查时无需制造改动循环。不能只做结构检查后宣称视觉验收完成。
6. 抽查每张事实型图片的来源台账、像素、裁切和展示尺寸；若更清晰的项目/PPTX/PDF 原图存在，低清截图不得通过验收。
7. 对案例页确认所有长段说明和指标已脱离截图成为原生文字，并与整套 PPT 的标题、副标题、Logo 和结论样式一致。

交付时准确说明：哪些是原生 PowerPoint 对象、哪些是 SVG/PNG 图片对象、哪些颜色能随主题联动、哪些媒体属于固定色例外，以及是否完成了全页 PowerPoint 渲染复核。
